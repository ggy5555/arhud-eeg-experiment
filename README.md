# 유리프 실험실: 작업 부담과 정보 화면

중앙 작업의 난이도와 주변 정보 화면의 제시 방식을 바꾸어 작업 기록, 자기보고, EEG 특징을 비교하는 **파일럿용 2D 모니터 실험**입니다. 실제 AR 기기나 자동차에서의 성능을 입증하는 실험은 아닙니다. 사이트는 정적 파일로 구성되어 GitHub Pages에서 실행됩니다.

## 실험 구조

- 쉬운 산수(받아올림 없음)·어려운 산수(받아올림 있음)와 간결·상세 화면을 조합한 네 조건입니다.
- 간결 화면은 두 공통 정보만 표시하고, 상태 확인 문항에서 스페이스바를 누르면 네 상태가 1.5초 동안 보입니다. 상세 화면은 두 공통 정보와 네 상태를 계속 표시합니다. 두 조건의 차이에는 정보량뿐 아니라 정보를 여는 조작도 포함됩니다.
- 한 블록은 60초입니다. 3초짜리 산수 문항 네 개와 상태 확인 문항 한 개를 네 번 반복합니다. 블록 후 참가자가 정신적 노력을 0~10점으로 평가합니다.
- 파일럿은 네 조건을 한 번씩, 본실험은 네 조건을 라운드마다 한 번씩 총 여섯 라운드로 진행합니다. 라운드 안 순서는 섞이며, 세션의 시드와 문항이 JSON에 기록됩니다. 라운드 사이에는 휴식 화면이 나옵니다.
- 시작 전 장비와 과제 난이도, 표시 시간, 수동 트리거 지연 및 데이터 품질을 파일럿에서 점검하고 팀이 절차를 정해야 합니다. 특정 결과가 나오도록 유도하거나 예시 결과를 실험 결과로 사용하지 마세요.

## 실험 진행

1. PC의 일반 브라우저에서 페이지를 열고 익명 참가자 코드와 세션 코드를 입력합니다. 처음에는 **파일럿**을 선택합니다. 실험 중 같은 세션을 여러 탭에서 열지 않습니다.
2. MeasureWiz 앱에서 EEG 녹화를 시작합니다. 사이트는 장비에 직접 연결되지 않습니다.
3. 각 블록 시작 안내에서 앱의 **trigger point**를 수동으로 누르고, 이어서 사이트의 확인 버튼을 누릅니다. 시작 후 60초 동안 산수와 상태 문항에 F(O) 또는 J(X)로 응답합니다.
4. 종료 안내가 나오면 앱에서 다시 trigger point를 누르고 사이트에서 확인합니다. 이어서 자기보고를 선택합니다. 사이트 확인 시각은 장비에서 트리거를 누른 실제 시각이 아닙니다.
5. 모든 블록을 마치면 세션 JSON과 기록 CSV를 내려받고, 장비 앱의 원본 EEG CSV도 익명 코드에 맞춰 별도로 보관합니다. 중간에도 JSON 백업을 내려받을 수 있습니다.

화면을 벗어나거나 실행 중 새로고침하는 등 블록이 중단되면 부분 기록과 사유가 남습니다. 같은 조건을 새 문항으로 다시 하거나 그 블록을 제외할 수 있습니다. 화면이 심하게 지연된 블록 등은 플래그로 표시되며 모델의 유효 블록에서 제외합니다.

사이트는 현재 브라우저에 **한 세션**을 임시 보관합니다. 다른 세션을 만들면 기존 임시 기록을 교체하므로 먼저 JSON을 저장해야 합니다. 브라우저 저장소를 지우거나 다른 브라우저·기기를 사용하면 임시 기록이 없어질 수 있습니다. JSON에는 전체 세션과 문항·이벤트가, CSV에는 각각 문항·블록·이벤트 기록이 담깁니다.

## EEG 파일 분석

1. **데이터 분석**에서 먼저 실험 JSON 또는 현재 브라우저 기록을 불러온 다음 MeasureWiz CSV를 선택합니다. CSV는 브라우저 안에서만 읽고 분석하며 사이트가 별도 서버로 업로드하지 않습니다.
2. `#Frequency`가 512Hz인 파일을 지원합니다. 여러 파일을 연결한다면 녹화 순서를 직접 조정하고 경계와 누락·녹화 공백을 확인합니다. `Time` 열은 정렬하거나 중복 제거하지 않으며 파일의 행 순서로 표본을 읽습니다.
3. 연구 노트와 장비 기록을 대조해 각 완료 블록의 시작·종료 트리거 번호를 직접 입력합니다. 임의 자동 매칭은 하지 않습니다. 두 기기의 시간차와 수동 트리거 오차는 별도 파일럿에서 확인해야 합니다. 프로그램의 확인 체크만으로 동기화가 증명되지는 않습니다.
4. 트리거 간격이 60초에서 4초를 넘게 벗어난 구간, 트리거 누락·중복, 시간순 충돌 또는 문제가 표시된 블록은 제외합니다. 양끝을 각각 5초 제외하고, 유효 구간이 30초 이상이어야 특징을 계산합니다. 트리거가 하나뿐인 파일에서는 블록 특징을 만들 수 없습니다.
5. 후보 전처리로 1~40Hz 양방향 필터, 4초 Hann 창의 50% 중첩 Welch 추정, theta(4~8Hz)와 alpha(8~12Hz) 파워의 `log(theta/alpha)`를 사용합니다. 원자료에서 창별 진폭이 설정값(초기값 ±150µV)을 넘거나 Quality가 0이면 해당 창을 제외합니다. 측정기의 Quality 의미, 눈 깜박임·근전도 영향, 진폭 기준 및 필터의 잡음 전파는 장비와 자료에 맞춰 검토해야 합니다. 값이 유효하더라도 그것만으로 정신적 부담의 진단이나 신경 원인을 확정할 수는 없습니다.
6. 분석을 마친 뒤 **분석 포함 JSON**과 특징 CSV를 저장합니다. 원본 EEG는 수정하지 말고 별도로 보관합니다. 아주 큰 CSV는 브라우저 메모리와 처리 시간의 제약을 받을 수 있으므로 기기에서 미리 시험하세요.

## 비교 모델과 화면 선택 시연

조건과 행동 기록을 쓰는 모델 A, 여기에 EEG 특징을 추가한 모델 B, 학습 자료의 평균 점수를 기준으로 삼는 단순 모델을 비교합니다. 같은 참가자의 한 라운드를 평가용으로 남기고 나머지 유효 라운드에서만 결측값 대체·표준화·회귀를 학습합니다. A와 B는 같은 평가 블록의 자기보고 예측 평균 절대 오차(MAE)를 비교합니다. 학습에는 유효 블록 16개 이상과 네 조건 각각 3개 이상이 필요합니다. 작은 표본과 같은 세션 내 평가라는 한계를 고려해 탐색적으로 해석해야 합니다.

선택 시연은 선택한 기준 블록 **이전** 자료로 학습하고 그 블록의 기록으로 점수를 추정하여 다음에 사용할 화면을 고릅니다. 기본 기준인 7점은 임시 후보이며 진단 기준이 아닙니다. 시연에서 고른 화면으로 별도 블록을 실행할 수 있지만, 과거 기록은 바뀐 화면에서의 성과가 아니며 실제 효과를 보려면 새로운 비교 실험이 필요합니다. EEG 실시간 제어 기능은 없습니다.

## 개발 및 배포

의존성 설치 없이 Node.js에서 `npm test`로 알고리즘 검사를 실행합니다. 기본 브랜치에 올리면 기존 GitHub Actions 워크플로가 검사를 통과한 뒤 저장소 루트를 GitHub Pages에 배포합니다.

`?qa=1`은 개발 확인용으로 문항 시간을 단축합니다. 이 모드의 기록은 `QA`로 표시되며 **실제 연구에 사용할 수 없습니다**. 참가자 정보, 실험 기록, EEG 원본 및 개인 파일은 공개 GitHub 저장소에 올리지 마세요.
